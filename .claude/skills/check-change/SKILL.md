# check-change

1. `git status` と `git diff` で、変更したファイルと内容を確認する。仕様(設計書や依頼内容)と照らし合わせる。
2. 既存の設定(README、pyproject.toml、package.json、Makefile、CI設定など)から、正しい検査コマンドを特定する。**存在しないコマンドを想像で書かない。** 見つからなければ「検査コマンドなし」と記録する。
3. 開発環境で、関連テストと必要な検査(lint、型チェック、構文チェックなど)を実行する。
4. 失敗を隠すために、検査対象・期待結果・合格条件を変更しない。テストを直す必要があるなら、理由を説明する。
5. 修正できない問題は、原因と再現手順を報告する。
6. 最後に次の形で報告する。実行できなかった検査を、実行済みと書かない。
   - **変更ファイル**:
   - **確認済み**: 実行したコマンドと結果
   - **未確認**: 確認できなかったことと理由
   - **残る問題**:
   - **戻し方**: 例) `git revert <commit>`
